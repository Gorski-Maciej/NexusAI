WSKAŹNIKI MIERZALNEJ PEWNOŚCI (definicje + bramki CI)
------------------------------------------------------------------------------
Definicje (wspólny słownik dla całego łańcucha raportów):
- LCI (Legal Coverage Index) = punkty prawne pokryte regułami / wszystkie
  punkty × 100. CEL: ≥ 99%. Źródło: LEGAL_COVERAGE.md + legal_coverage_gaps.json.
- TCL (Total Canonical Coverage) = reguły z _legal_basis kanoniczną / reguły
  materialne × 100. CEL: 100%. Źródło: legal_basis_audit.json (obecnie 5,33%!).
- RV (Reference Validity) = reguły OK / reguły z podstawą × 100. CEL: 100%.
  Obecnie: 655 OK / (655+10493+268+870) = 5,33% ⚠️ (wymaga czyszczenia).
- UVR (Unverified) = reguły bez weryfikowalnej podstawy (MISSING + UNKNOWN_ACT).
  CEL: 0. Obecnie: 268 + 870 = 1 138 ⚠️.
- Duplikaty rule_id = 0 (obecnie 369 wg MANIFEST).
- Stuby = reguły matched:false / placeholdery = 0 (obecnie warstwa UoR/PKPiR).
- Hardcode = stałe liczbowe spoza bundles/legal_reference_canon.json = 0.

Bramki CI (proponowany pipeline):
1. validate_rules.py --strict (9 walidacji) → FAIL przy jakimkolwiek błędzie
2. lint_rego_rules.py (6-check) → FAIL przy błędach składni/stylu
3. tautology_guard.py → BLOCKING
4. dead_rule_detector.py → FAIL przy duplikatach rule_id > 0
5. legal_basis validator → FAIL przy RV < 90% (po domknięciu P0-2) 
6. Generator wskaźników (nowy) → publikuje LCI/TCL/RV/UVR do bundles/metrics.json

GENIALNE POMYSŁY ENTERPRISE (innowacyjne ulepszenia wyprzedzające
profesjonalistów — min. 12)
------------------------------------------------------------------------------
1. **Auto-Legal-Twin Generator**: z docs/Bbb automatycznie buduje graf
   akt→artykuł→reguła→test (zamiast ręcznych szablonów LEGAL_COVERAGE).
2. **Decision Certificate w każdym werdykcie**: bundle_version + rule_version +
   threshold_version + hash Merkle — „dowód z przeszłości" dla kontroli KAS.
3. **Law Radar w runtime**: API powiadomień o projektach ustaw (RCL/ISAP) —
   przedsiębiorca dowiaduje się o zmianie prawa ZANIM wejdzie w życie.
4. **Declarative Change Wizard**: opis zmiany w języku naturalnym →
   generator diffa reguł + testów + kanary (mniej błędów ludzkich).
5. **Golden Replay Bank**: snapshoty werdyktów per bundle — porównywanie
   regresji przy każdej zmianie (zero cichych regresji).
6. **Automatyczny remidiate RV**: skrypt klasyfikujący NON_CANONICAL →
   kanoniczne węzły (30 aktów) z raportem zmian dla prawnika.
7. **Sharding z auto-balancingiem**: mierzenie czasu per shard, dynamiczna
   rekonfiguracja routingu (O(1) zawsze).
8. **Śledzenie limitu zwolnienia VAT 200k w czasie rzeczywistym** z alertami
   przed przekroczeniem (kombinacja micro+macro).
9. **Health-Score JDG**: jeden wskaźnik 0–100 (LCI+TCL+RV+UVR+duplikaty+testy)
   na dashboardzie /jdg/health — „temperatura systemu".
10. **Temporalne testy nowelizacji**: dla każdej zmiany prawa testy
    SHADOW→ACTIVE z datami granicznymi (co było przed/po zmianie).
11. **Zero-Stub Policy**: CI blokuje merge przy matched:false w warstwach
    deklarowanych jako live (wymusza domknięcie UoR/PKPiR).
12. **Interaktywny Katalog Reguł**: przeszukiwanie 11 452 rule_id po artykule
    ustawy, dacie ważności, pakiecie — dla księgowego i audytora.
13. **Self-healing bundles**: przy wykryciu niespójności manifestu automatyczne
    odtworzenie z kodu (reduce ludzkich błędów w release).
14. **Decyzyjny dziennik (Decision Log)**: append-only log wszystkich werdyktów
    z pełnym dowodem — gotowy materiał na obronę przed KAS.
