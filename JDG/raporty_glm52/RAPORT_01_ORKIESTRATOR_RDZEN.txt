R01-INN-01 routing_path_trace — deterministyczny routing z debugowaniem ścieżki
  • select_path(ctx): O(1) wybór ścieżki (FULL_CHAIN_CROSS_BORDER /
    FULL_CHAIN_ENTITY_NON_ACTIVE / SHARDED_DOMESTIC_SALE /
    SHARDED_DOMESTIC_PURCHASE / FULL_CHAIN_FALLBACK).
  • routing_path_trace: selected_path + pełny routing_context + debug line
    (path|tx|entity|xb|eval) + deterministyczny (INV-040).
  • Korzyść: audyt ścieżki decyzyjnej bez debuggera OPA; identyczny kontekst
    = identyczna ścieżka (ewaluacja różnicowa F3).

R01-INN-02 verdict_25_field — werdykt 25-polowy
  • verdict_25_fields: słownik kanoniczny 25 pól (4 metadane + 15 decyzyjnych
    + temporalność + 5 dowodowych).
  • verdict_complete()/missing_verdict_fields(): bramka kompletności.
  • Korzyść: werdykt niekompletny nigdy nie jest CERTAIN (INV-043) — zero
    „cichych" braków pól w decyzji finansowej.

R01-INN-03 decision_cache_runtime — cache decyzji
  • cache_input_hash: deterministyczny klucz (nip|invoice|direction|data|
    temporal|bundle_version — INV-040).
  • decision_cache_runtime: TTL (300000 ms default, hot-reload przez input),
    hit/miss, tamper-evident (merkle_verify P03 INN-12).
  • Korzyść: powtarzalne decyzje bez ponownej ewaluacji; deterministyczny
    replay (F3 V2).

R01-INN-04 time_travel_guard — spójność time-travel
  • Aktywny przy temporal_evaluation_date ≠ "": consistent = ted ≤ ed.
  • Korzyść: korekta deklaracji nie zmienia historycznych werdyktów
    (INV-025); rozjazd dat → TRIAGE, nigdy AUTO_POST.

R01-INN-05 safe_merge_integrity — runtime verification allowlist (INV-042)
  • immutable_allowlist: lustro main_jdg (ZUS, sickness_benefits,
    enterprise_benefits, health_contribution, business, fortress).
  • violations: pakiet allowlisty z matched=true bez immutable_verdict=true;
    overwrite_warning_present: wykrycie IMMUTABLE_VERDICT_OVERWRITE.
  • Korzyść: „konstytucja" safe_merge egzekwowana w runtime, nie tylko w CI.

R01-INN-06 priority_conflict_detector — zderzenia priorytetów (INV-018)
  • priority_conflicts: zbiór priorytetów, dla których ≥2 pakiety matched.
  • Korzyść: wykrycie niejednoznaczności First-Match-Wins przed AUTO_POST.

GŁÓWNA REGUŁA: decide = jdg.r01_orchestrator_core_innovations.orchestrator_core_report
  (priority 290, _routing REPORT, aktywowana flagą
  input.jdg_entrepreneur.r01_orchestrator_core_check; w normalnym ruchu
  no_match — nie nadpisuje decyzji).
