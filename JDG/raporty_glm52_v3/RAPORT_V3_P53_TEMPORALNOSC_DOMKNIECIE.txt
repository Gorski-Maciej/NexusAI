  mitigacja: L03/Q02. Akceptacja: pillars=3/4 jawne w bundlu; test rego 3.

I04 Transitional rules register — Problem: zasady przejściowe „w głowie”.

  modelowana: tak/nie, źródło w kodzie) + MANUAL_REVIEW przy brakach.

Akceptacja: 6 wpisów, 5 modelowanych; test pytest 5; rego 9. Zależności:
  P26, P18, P41.
I05 Gap/overlap interval validator — Problem: dziury/nakładki okien.
Mechanizm: algebra interwałów na versions[] parametrów (spójna z
  temporal_interval_gate.py); gaps>0 lub overlaps>0 = BLOCK (INV-037).

  aktywna wersja na datę. Ryzyko: edge-case 1-dniowe okna → zdefiniowane
  (a_to < b_from−1d = gap). Akceptacja: 0/0 w bundlu; testy rego 7/7b.
Zależności: P05, INV-037, P39.
I06 Epoch registry — Problem: „jaka wersja prawa obowiązywała?” bez danych.
Mechanizm: epoki z cięć valid_from parametrów; hash snapshotu parametrów
  per epoka (SHA-256); lookup po dacie; data poza oknami = NEEDS_ADVICE.
Bezpieczeństwo: nierozpoznana data ≠ najbliższa epoka (fail-closed).
Ryzyko: jedna epoka bazowa (rzeczywisty stan) → rozszerzanie automatyczne.
Akceptacja: hash obecny; testy rego 10/10b/10c (granica day-0). Zależności:
  P03, P46.

Bezpieczeństwo: symulacja nie może zanieczyścić decyzji/archiwum.
Ryzyko: brak flagi przy potrzebie → jawny NO_MATCH (nie cichy DRAFT).
Akceptacja: testy rego 11/11b. Zależności: V2 Declarative Change, P08.

Ryzyko: kalendarz pusty (L02) → śledzone jako luka, nie maskowane.
Akceptacja: bundle I08; test rego (ścieżka I08). Zależności: P08, P38.
