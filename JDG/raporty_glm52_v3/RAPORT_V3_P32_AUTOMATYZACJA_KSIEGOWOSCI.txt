5.1 Ingest dokumentów i klasyfikacja (AN01)
  * Tabela dowodów: auto_booking_pipeline (I01), idempotency_keys (I02),
    needs_advice_queue (I04), four_eyes_flow (I09), automation_limits (I11);
    narzędzia rdzenia: ksef_offline_queue.py, ksef_outbox.py.
  * Wnioski:
    1) Wejście dokumentu przechodzi przez idempotencję (hash dokumentu jako
       klucz) PRZED klasyfikacją — podwójne dostarczenie = zerowy efekt + alarm
       (double_posted = BLOCK).
    2) Klasyfikacja jest regułowa (OPA), nie konfiguracyjna: pewność < 95%
       (v3_p32_auto_post_min_confidence) = TRIAGE — NEEDS_ADVICE, nigdy cichy
       AUTO_POST (AP07 zamknięty testem test_p32_i01_low_confidence_triage).
    3) Dokument niekompletny (brak NIP/daty) trafia do jednej kolejki
       NEEDS_ADVICE z klasterizacją (I04) — niepewności nie giną, a P10 golden
       replay sugeruje decyzję człowiekowi.
  * Luki: brak nowych P0/P1; P3=1 (ISAP).

5.2 Wycena i ewidencje (VAT, PKPiR/UoR) (AN02)
  * Tabela dowodów: penny_boundary_tests (I06), seasonal_replay (I07),
    bank_reconciliation (I05); narzędzia: vat_rate_engine.py,
    vat_mpp_auto_detector.py, uor_double_entry.py.
  * Wnioski:
    1) Wyliczenia VAT używają reguł macro+micro spójnie (kampania P13 pokryła
       deduction_rights/MPP/whitelist z testami natywnymi — brak duplikacji).
    2) Granice groszowe (0,00/0,01/99999999,99) są DANYMI TESTOWYMI generowanymi
       per reguła wyliczania (P36) — hardcode granic = BLOCK (test
       test_p32_i06_hardcode_block).
    3) Replay sezonowy (I07) odpowiada na pytanie „czy starą deklarację wydałbyś
       dzisiaj inaczej": dryf decyzji > 0 = TRIAGE, > 10× limitu = BLOCK.
  * Luki: brak nowych P0/P1.

5.3 Deklaracje i płatności (AN03)
  * Tabela dowodów: pre_deadline_corrections (I08), external_backpressure (I12),
    bank_reconciliation (I05); narzędzia: jpk_generator.py, jpk_validator.py,
    jpk_autogen.py, zus_calendar.py.
  * Wnioski:
    1) Terminy płatności/deklaracji pochodzą z kalendarza zbiorczego P25 (dane),
       nie z hardcodu; okno korekt pre-deadline = 7 dni (v3_p32_correction_
       window_days) — błędy wykryte w oknie bez propozycji korekty = TRIAGE.
    2) Priorytet płatności (ZUS vs VAT vs PIT) jest regułowy i testowany
       (kampania legacy: test_payment_priority_service, test_priority_engine).
    3) Awaria KSeF/MF wstrzymuje pipeline w kontrolowany sposób (I12): offline
       mode + kolejka + raport zgodności terminowej; ryzyko terminowe przy
       AKTYWNYM łączu (brak backpressure) = BLOCK.
  * Luki: brak nowych P0/P1.

5.4 Zamknięcie miesiąca i archiwum (AN04)
  * Tabela dowodów: two_phase_close_month (I03), document_traceability (I10),
    needs_advice_queue (I04); narzędzia: uor_closing_engine.py.
  * Wnioski:
    1) Zamknięcie miesiąca jest atomowe w 2 fazach: prepare (wykrywanie
       niezgodności) → commit (tylko przy spójnych ewidencjach + zatwierdzeniu);
       commit z niezgodnością lub bez 4-eyes = BLOCK (test
       test_p32_i03_commit_mismatch_block).
    2) Otwarcie miesiąca po zamknięciu wymaga dowodu audytowego i 4-eyes —
       ślad w decision certificate (V2 F4).
    3) Archiwum: pojedynczy identyfikator dokumentu prowadzi przez wszystkie
       etapy (I10); zerwany łańcuch traceability = BLOCK (limit 0);
       zgodność z WORM (P31 I07, P43).
