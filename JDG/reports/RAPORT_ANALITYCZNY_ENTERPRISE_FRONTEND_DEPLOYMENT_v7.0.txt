1.3 Navigator 2.0 — Pelna Analiza Routera
------------------------------------------

NexusRouter (router.py) implementuje Navigator 2.0 z PELNA historia nawigacji:

FUNKCJE NAWIGACYJNE:
  push_view(route, content)    — Dodaje widok na stos (slide in)
  pop_view()                   — Zdejmuje widok ze stosu (slide out)
  replace_view(route, content) — Zastepuje biezacy widok (fade)

TEMPLATE ROUTE — URL Pattern Matching:
  ft.TemplateRoute("/invoices/inv-123/edit")
    .match("/invoices/:id")      → True, id="inv-123"
    .match("/invoices/:id/edit") → True, id="inv-123"

ZAREJESTROWANE TRASY:
  "/"                      → Dashboard
  "/invoices"              → Lista faktur
  "/invoices/:id"          → Szczegoly faktury
  "/invoices/:id/edit"     → Modal edycji faktury
  "/briefing"              → Podsumowanie dnia
  "/partner"               → Panel partnera
  "/tasks"                 → Monitor zadan
  Inne                     → 404 — Nie znaleziono

ROUTE GUARD:
  RouteGuard sprawdza autoryzacje PRZED renderem widoku:
  - Trasy publiczne: /login, /register, /reset-password
  - Token JWT z page.client_storage
  - Brak tokena → przekierowanie do /login z komunikatem
  - Blad buildera → error page z przyciskiem powrotu do Dashboardu

BREADCRUMB NAVIGATION:
  Dynamicznie budowany z page.views:
  [IKONA_HOME Dashboard > FAKTURY > Faktura #inv-123]
  Kazdy okruszek jest klikalny — nawiguje do poprzedniego widoku.

URL = STATE:
  Dwukierunkowa synchronizacja URL <-> stan widoku:
  - Filtry w URL: /invoices?status=APPROVED&q=faktura&page=2
  - parse_query_context() — parsowanie query params
  - update_url_with_filters() — aktualizacja URL przy zmianie filtrow
  - page.client_storage — zapamietanie ostatniej sciezki + filtrow

ANIMACJE PRZEJSC:
  TransitionConfig — centralna konfiguracja animacji:
    PUSH_TRANSITION    = OPEN_UPWARDS  (widok wjezdza od dolu)
    POP_TRANSITION     = NONE          (natychmiastowy powrot)
    REPLACE_TRANSITION = ZOOM          (zoom przy zmianie)

  FadeInContent — opacity 0->1 przy montowaniu widoku
  SlideFadeContent — slide + fade-in kombinacja
  animated_card — scale 1.0->1.02 na hover

MODAL ROUTING:
  /invoices/:id/edit otwiera modal overlay zamiast pelnego widoku:
  - Container 80% szerokosci, 85% wysokosci okna
  - AppBar z przyciskiem zamkniecia
  - Shadow BoxShadow(blur_radius=20)

WINDOW LIFECYCLE:
  page.window_prevent_close = True
  page.on_window_event — obsluga close, focus, resize
  Zamkniecie → AlertDialog "Czy na pewno chcesz zamknac?"

OCENA: 9.5/10 — Navigator 2.0 jest ZAIMPLEMENTOWANY W PELNI. TemplateRoute,
RouteGuard, Breadcrumb, URL=State, Modal Routing, animacje przejsc — to
jest KOMPLETNY system routingu klasy Enterprise. To jest NAJLEPSZY element
calego frontendu.

1.6 Offline-First — Lokalne Dane i Synchronizacja
--------------------------------------------------

Komponenty offline-first:

  - Type-safe przez msgspec.Struct (UserPreferences)
  - Token JWT w page.client_storage
  - Preferencje: theme, compact_mode, language, items_per_page
  - Automatyczne czyszczenie sesji

  - In-memory cache z TTL 5 sekund
  - Cache keys dla faktur, analityki, dashboardu

  - nexus_last_route — ostatnia sciezka miedzy sesjami

  - nexus_user_prefs — preferencje uzytkownika (msgspec)

Web Mode:
  - ft.AppView.WEB_BROWSER — SPA w przegladarce
  - TemplateRoute dla URL pattern matching
  - Shimmer loading podczas inicjalizacji

OCENA: 8.0/10 — Mechanizmy offline-first sa solidne, ale brakuje:
- Pelnej synchronizacji offline → online (queue pending requests)
- Service Worker dla PWA (web mode)
- Indeksowane dane w lokalnej bazie SQLite dla pelnego offline

1.7 Chart Widgets — Natywne Wykresy Flet bez Matplotlib
--------------------------------------------------------

charts.py implementuje 5 typow wykresow na natywnych komponentach Flet:

1. revenue_expense_chart() — Grouped Bar Chart
   Przychody (zielony) vs koszty (czerwony) miesiecznie.
   2 slupki na grupe (revenue + expense).

2. cashflow_line_chart() — Combined Bar + Line Chart
   Slupki: okresowe przeplywy (niebieski, 40% opacity)
   Linia: skumulowane przeplywy (zielony, 90% opacity, curved)
   Stack z przezroczystym overlayem.

3. vat_pie_chart() — Donut Chart
   Struktura VAT z center_space_radius=0.55 (donut hole).
   Tekst w srodku: laczna suma VAT.
   Badge z etykieta kategorii.

4. monthly_trend_line_chart() — Line Chart
   Trend miesieczny z zaokraglona linia (curved=True).
   Prevents overshoot na krawedziach (prevent_curve_edges=True).

5. top_suppliers_bar_chart() — Horizontal Bar Chart
   Top 5 dostawcow wg wydatkow.
   Odwrocona kolejnosc (top-at-top).

INNOWACJA 1: "Delta Updates" — Aktualizacje Roznicowe
  Zamiast pobierac CALY plik .exe (100+ MB), pobieraj tylko ROZNICE
  miedzy wersjami (binary diff). Format bsdiff/bspatch.
  Redukcja downloadu o 80-95% dla malych aktualizacji.
  Oszczednosc: z 100 MB do 5-20 MB na aktualizacje.

INNOWACJA 2: "Phased Rollout" — Stopniowe Wdrazanie
  Nowe wersje sa wdrazane stopniowo:
  - 5% uzytkownikow → monitoruj bledy przez 24h
  - 25% → monitoruj przez 48h
  - 100% po walidacji
  Mozliwosc automatycznego rollbacku jesli error rate > 2%.

INNOWACJA 3: "Background Update Download"
  Aplikacja pobiera aktualizacje W TLE, gdy uzytkownik pracuje.
  Gdy gotowa → cicha podmiana plikow i komunikat:
  "Aktualizacja gotowa. Uruchom ponownie by zastosowac."
  Zero przestojow — aktualizacja jest gotowa zanim uzytkownik
  ja zobaczy.

  CI automatycznie wykrywa problemy z buildem:
  - Testy nie przechodza → nie oznaczaj jako "failed",

  - Brakujaca biblioteka → automatyczne dodanie do
    package-config.yml
  - Build timeout → zwieksz timeout tylko dla tego joba
  - Crosshair znalazl kontrprzyklad → utworz issue

INNOWACJA 5: "Signed SBOM Registry"
