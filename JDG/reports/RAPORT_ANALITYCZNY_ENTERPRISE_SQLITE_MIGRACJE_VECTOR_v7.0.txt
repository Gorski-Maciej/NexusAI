2.1. SQLCIPHER AES-256 — KONFIGURACJA
--------------------------------------------------------------------

STATUS: DOSKONALA — Wielopoziomowe bezpieczenstwo

Architektura bezpieczenstwa:

  [NEXUS_SQLCIPHER_KEY env] -> [SQLCipherConfig] -> [PRAGMA key]
                                                          |
  +-------------------------------------------------------+
  |
  [AES-256-CBC encryption]
  |
  +-- cipher_page_size=4096 (strona 4KB)
  +-- kdf_iter=64000 (PBKDF2_HMAC_SHA512)
  +-- hmac_algorithm=HMAC_SHA512
  +-- cipher_memory_security=ON
  +-- cipher_compatibility=4 (profil bezpieczenstwa)

Dual detection SQLCipher:
  1. Proba PRAGMA cipher_version (natywnie skompilowany)
  2. LD_PRELOAD libsqlcipher.so przez ctypes.CDLL

Fallback dla starszych wersji:
  cipher_page_size=4096 + kdf_iter=64000 zamiast compatibility=4

OCENA KONFIGURACJI: 95/100

Zalety:
+ AES-256-CBC z PBKDF2_HMAC_SHA512
+ cipher_compatibility=4 — najnowszy profil bezpieczenstwa
+ cipher_memory_security=ON — klucze nie sa w swappie
+ hmac_use=ON — uwierzytelnianie kazdej strony
+ plaintext_header=FALSE — brak metadanych plaintext

Ograniczenia:
- Brak wsparcia dla AES-256-GCM (tylko CBC)
- Brak hardware security module (HSM)

2.3. WAL MODE + SZYFROWANIE — KONFLIKTY?
--------------------------------------------------------------------

NIE — WAL mode dziala poprawnie z SQLCipher:

- PRAGMA journal_mode=WAL ustawiane PO PRAGMA key
- WAL plik jest ROWNIEZ szyfrowany
- SYNCHRONOUS=NORMAL dla wydajnosci
- Connection pool z QueuePool (5-15 polaczen)

PRAGMA po connect():
  1. PRAGMA key (PIERWSZA!)
  2. PRAGMA cipher_compatibility=4
  3. PRAGMA journal_mode=WAL
  4. PRAGMA synchronous=NORMAL
  5. PRAGMA foreign_keys=ON
  6. PRAGMA cell_size_check=ON
  7. PRAGMA cache_size=-51200 (200MB)
  8. PRAGMA temp_store=MEMORY
  9. PRAGMA trusted_schema=OFF
