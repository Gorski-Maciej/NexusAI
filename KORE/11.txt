
Po analizie całości dokumentów (1–10) i kodu źródłowego, nawet po wdrożeniu wszystkich opisanych wcześniej zmian, zidentyfikowałem kolejne, subtelne luki, które dzielą system od poziomu Advanced/Autonomous. Nie są to błędy w obecnym planie, ale warstwy dojrzałości, które trzeba dodać, by system był naprawdę „pancerny”. Poniżej szczegółowa analiza i konkretne rozwiązania.

---

1. Brak systematycznych testów wydajności i skalowalności (Performance Engineering)

Niedociągnięcie:
Dokumenty opisują testy jednostkowe, integracyjne, chaosowe i kontraktowe (Schemathesis), ale pomijają testy obciążeniowe (load testing) i wydajnościowe (performance testing). W systemie księgowym, gdzie pod koniec miesiąca następuje kumulacja operacji, infrastruktura musi być zwymiarowana i sprawdzona pod kątem maksymalnego obciążenia.

Ryzyko:
System, który przechodzi testy funkcjonalne, może „paść” przy 100 równoczesnych użytkownikach lub przy przetwarzaniu 1000 faktur na godzinę. Bez testów wydajności nie wiadomo, gdzie są wąskie gardła (np. SQLite, NATS, GPU).

Rozwiązanie – Load Testing z k6 i profiling:

· Zintegrować k6 (Grafana) jako narzędzie do testów obciążeniowych w CI/CD (np. po deploymencie na staging).
· Zdefiniować scenariusze realistyczne: „50 księgowych przesyła faktury w ciągu 5 minut”, „100 równoczesnych zapytań o dashboard”.
· Mierzyć kluczowe metryki: p95 opóźnienia API, przepustowość (faktury/min), zużycie RAM/VRAM podczas testu.
· Wyniki zapisywać w VictoriaMetrics i monitorować trendy (regresje wydajności).
· Dla AI: profilować czas inferencji modeli przy różnych rozmiarach batcha.

Ulepszenie dla Nuitka:
Zastosować Profile-Guided Optimization (PGO) – uruchomić testy wydajności na skompilowanej binarce, zebrać dane profilowe i ponownie skompilować z --pgo dla optymalizacji najgorętszych ścieżek.

---

2. Zarządzanie zależnościami w monorepo uv a kompilacja Nuitka

Niedociągnięcie:
Plan zakłada użycie uv workspaces (monorepo). Nuitka podczas kompilacji musi „widzieć” wszystkie pakiety, ale mechanizm workspaces uv może tworzyć linki symboliczne lub specyficzną strukturę site-packages, która może nie być poprawnie obsługiwana przez --include-package Nuitka.

Ryzyko:
Brak poprawnej konfiguracji skutkuje błędami ModuleNotFoundError w skompilowanej binarce lub dołączeniem niepotrzebnych zależności, co zwiększa rozmiar binarki.

Rozwiązanie:

· Stworzyć dedykowany skrypt build.py (Invoke), który przed kompilacją Nuitka „spłaszcza” workspace do tymczasowego katalogu (np. kopiuje wszystkie pakiety do jednego drzewa).
· Jawnie testować importy w trybie --standalone na etapie CI, aby wykryć brakujące moduły.
· Użyć flag --include-package z pełnymi ścieżkami wewnątrz monorepo (np. libs.domain, apps.api).

---

3. Brak automatycznych testów bezpieczeństwa API (DAST) w CI/CD

Niedociągnięcie:
Schemathesis testuje kontrakt API, ale nie pokrywa testów podatności bezpieczeństwa, np. SQL Injection, XSS, IDOR (Insecure Direct Object Reference). W systemie finansowym to krytyczne.

Ryzyko:
Nawet przy poprawnym JWT i RBAC, błąd w kodzie może pozwolić na odczyt cudzych faktur (IDOR) lub wstrzyknięcie kodu przez payload.

Rozwiązanie – Integracja OWASP ZAP i CodeQL:

· W pipeline CI/CD po deploymencie na staging uruchomić OWASP ZAP w trybie pełnego skanowania (baseline scan + active scan) przeciwko API.
· Skanować kod źródłowy za pomocą CodeQL (GitHub) lub Semgrep w poszukiwaniu wzorców podatności.
· Dodać dedykowane testy bezpieczeństwa dla kluczowych endpointów (np. próba dostępu do faktury innego tenantu).

---

4. Brak strategii internacjonalizacji (i18n) dla UI Flet

Niedociągnięcie:
System jest pisany po polsku, ale w miarę rozwoju może być używany przez firmy zagraniczne. Brak mechanizmów internacjonalizacji utrudni adaptację.

Ryzyko:
Wprowadzenie i18n po fakcie jest bardzo kosztowne i wymaga przerabiania całego UI oraz treści generowanych przez AI.

Rozwiązanie – i18n od podstaw:

· Zastosować Babel do znakowania wszystkich stringów w kodzie Pythona i szablonach PDF.
· Dla Flet: przenieść wszystkie teksty do słowników JSON ładowanych na podstawie wybranego języka.
· AI prompty muszą być wielojęzyczne – przechowywać je w prompts/{lang}/.
· W DuckDB i logach operacyjnych przechowywać identyfikatory komunikatów zamiast twardych stringów.

---

5. Niezawodność obsługi bardzo dużych plików (>1 GB)

Niedociągnięcie:
Mechanizm strumieniowania fsspec działa dla plików o standardowych rozmiarach, ale nie ma zabezpieczeń dla ekstremalnie dużych załączników (np. faktura z 50-stronicowym załącznikiem w skanie 1200 DPI). To może spowodować wyczerpanie pamięci lub timeouty.

Ryzyko:
Przyjęcie takiego pliku może zablokować pipeline OCR na wiele minut i wpłynąć na inne zadania.

Rozwiązanie:

· W konfiguracji Litestar ustawić maximum_request_body_size (np. 50 MB) dla uploadu faktur. Większe pliki odrzucać z kodem 413.
· Dla wyjątkowych przypadków (załączniki) stworzyć osobny endpoint z limitem 500 MB i dedykowanym workerem, który nie blokuje głównej kolejki OCR.
· Jeśli plik jest większy niż dostępna pamięć /dev/shm, system powinien automatycznie przełączyć się na przetwarzanie strumieniowe z dysku (fallback).

---

6. Tryb offline dla Infiscal – zarządzanie sekretami bez sieci

Niedociągnięcie:
System jest projektowany jako „offline-first”, ale Infiscal jest serwisem sieciowym. W przypadku braku łączności, aplikacja nie może pobrać sekretów przy starcie.

Ryzyko:
Brak dostępu do Infiscal uniemożliwia uruchomienie systemu, co jest sprzeczne z ideą offline-first.

Rozwiązanie – Lokalny cache sekretów:

· Przy pierwszym udanym pobraniu sekretów z Infiscal, zapisać je lokalnie w zaszyfrowanym pliku (SOPS + Age) na dysku.
· Przy starcie aplikacja najpierw próbuje Infiscal (timeout 5s); jeśli niedostępny – używa lokalnego cache.
· Lokalny cache ma TTL (np. 24h), po którym wymagane jest połączenie z Infiscal w celu odświeżenia.
· Rotacja sekretów wymusza aktualizację cache poprzez NATS.

---

7. Automatyczna weryfikacja integralności danych po migracjach Alembic

Niedociągnięcie:
Plan zakłada użycie Alembic do migracji SQLite. Jednak po migracji schematu (np. dodanie kolumny) nie ma automatycznego sprawdzenia, czy dane nie zostały uszkodzone.

Ryzyko:
Błędy w skryptach migracyjnych mogą spowodować cichą utratę danych (np. ustawienie NULL w kolumnie NOT NULL).

Rozwiązanie:

· Każda migracja Alembic musi zawierać funkcję upgrade() i downgrade(), a po upgrade() uruchamiany jest test „sanity check” (np. czy liczba rekordów w tabeli przed i po migracji jest taka sama).
· W CI/CD na kopii bazy produkcyjnej automatycznie uruchomić migracje i zweryfikować sumy kontrolne kluczowych tabel.
· Dodać testy kontraktowe, które sprawdzają, czy nowe kolumny są poprawnie wypełniane przez aplikację.

---

8. Proaktywny skaner wycieków danych wrażliwych w logach

Niedociągnięcie:
Vector maskuje logi, ale robi to reaktywnie (na podstawie reguł). Nie ma mechanizmu, który cyklicznie skanuje już zapisane logi w poszukiwaniu niezamaskowanych danych wrażliwych (np. numerów NIP, które umknęły regułom).

Ryzyko:
Naruszenie RODO przy audycie, jeśli w logach znajdą się dane osobowe.

Rozwiązanie:

· Dodać zadanie cronowe, które raz dziennie skanuje ostatnie 24h logów (w DuckDB lub bezpośrednio pliki Parquet) za pomocą wyrażeń regularnych i heurystyk.
· W przypadku wykrycia potencjalnych wycieków, automatycznie maskuje je w kopiach zapasowych i wysyła alert do DPO (Data Protection Officer).
· Rozbudować reguły maskowania Vector o wzorce specyficzne dla polskich dokumentów (PESEL, REGON, NIP, numery kont bankowych).

---

9. Polityka wycofywania (deprecation) wersji modeli AI w Model Registry

Niedociągnięcie:
Model Registry przechowuje wersje, ale nie ma strategii usuwania lub archiwizacji starych modeli. Z czasem miejsce na dysku może się wyczerpać.

Ryzyko:
Marnowanie zasobów dyskowych i potencjalne pomyłki (przypadkowe użycie bardzo starego modelu).

Rozwiązanie:

· Określić politykę retencji: przechowywać ostatnie 3 aktywne wersje, pozostałe archiwizować do taniego storage (S3 Glacier) z metadanymi.
· Wprowadzić automatyczne testy regresji po każdym retreningu: nowy model nie może być gorszy niż poprzedni na Golden Dataset.
· Dodać UI w Flet do zarządzania modelami (przywracanie starszej wersji, porównywanie metryk).

---

10. Buforowanie telemetrii przy awarii OpenTelemetry Collector / VictoriaMetrics

Niedociągnięcie:
OpenTelemetry wysyła dane bezpośrednio do Collectora. Jeśli Collector lub VictoriaMetrics są niedostępne, dane telemetryczne są tracone.

Ryzyko:
Utrata cennych danych diagnostycznych podczas awarii (czyli dokładnie wtedy, gdy są najbardziej potrzebne).

Rozwiązanie:

· Skonfigurować OTel SDK z BatchSpanProcessor i OTLPSpanExporter z retry i backoffem.
· Dodać lokalny bufor dyskowy (file-based exporter) jako fallback – jeśli eksport sieciowy nie powiedzie się, spany są zapisywane na dysku i wysyłane po przywróceniu łączności.
· Monitorować stan bufora (metryka otel.exporter.queue_full).

---

11. Monitorowanie kosztów zasobów (FinOps) dla samodzielnego hostingu

Niedociągnięcie:
System działa na własnej infrastrukturze, ale nie ma mechanizmu monitorowania kosztów energii i zasobów, co jest istotne przy długoterminowym utrzymaniu.

Ryzyko:
Nie można zoptymalizować kosztów ani wykryć „kradzieży” zasobów przez wadliwe procesy.

Rozwiązanie:

· Wbudować w Pulumi i VictoriaMetrics metryki kosztowe: szacunkowy koszt CPU/h, RAM/h, transfer sieciowy (na podstawie stawek rynkowych).
· W dashboardzie Grafana wyświetlać „koszt przetworzenia jednej faktury” = (suma kosztów infrastruktury) / liczba faktur.
· Alertować przy anomaliach kosztowych (np. nagły wzrost zużycia GPU bez wzrostu liczby faktur).

---

12. Bezpieczeństwo plików tymczasowych tworzonych przez biblioteki ML

Niedociągnięcie:
Modele AI (PyTorch, ONNX, transformers) tworzą pliki tymczasowe (np. cache tokenizerów, shardy wag) w domyślnych lokalizacjach (/tmp lub ~/.cache). Mogą one zawierać fragmenty danych treningowych lub konfigurację.

Ryzyko:
Wyciek wrażliwych informacji (np. NIP-y z danych treningowych) lub możliwość podmiany plików cache przez atakującego.

Rozwiązanie:

· Ustawić zmienne środowiskowe HF_HOME, TORCH_HOME, TRANSFORMERS_CACHE na dedykowany, zaszyfrowany wolumen z restrykcyjnymi uprawnieniami.
· Czyścić cache przy każdym restarcie kontenera (w on_shutdown) lub montować jako tmpfs (pamięć ulotna).
· Monitorować rozmiar cache i usuwać najstarsze pliki (LRU).

1. Testy wydajnościowe i profilowanie (Performance Engineering)

Cel

Zapewnienie, że system działa stabilnie pod obciążeniem i nie ma regresji wydajności.

Rozwiązanie: Integracja k6 + VictoriaMetrics + PGO Nuitka

1.1. Scenariusze testowe k6

Utwórz plik tests/performance/scenarios.js:

```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';
import { Trend, Rate } from 'k6/metrics';

const invoiceUploadDuration = new Trend('invoice_upload_duration');
const dashboardQueryDuration = new Trend('dashboard_query_duration');
const errorRate = new Rate('errors');

export const options = {
    stages: [
        { duration: '2m', target: 10 }, // ramp-up
        { duration: '5m', target: 50 }, // peak – 50 księgowych
        { duration: '2m', target: 0 }, // ramp-down
    ],
    thresholds: {
        'invoice_upload_duration': ['p(95)<3000'], // 95% uploadów < 3s
        'errors': ['rate<0.01'], // mniej niż 1% błędów
    },
};

const BASE_URL = 'http://localhost:8000/api/v2';
const TOKEN = __ENV.NEXUS_TEST_TOKEN;

export default function () {
    const params = {
        headers: {
            'Authorization': `Bearer ${TOKEN}`,
            'Content-Type': 'application/json',
        },
    };

    // Scenariusz 1: Dashboard analytics
    const dashboardRes = http.get(`${BASE_URL}/analytics/summary`, params);
    dashboardQueryDuration.add(dashboardRes.timings.duration);
    errorRate.add(dashboardRes.status !== 200);

    // Scenariusz 2: Upload faktury (symulacja multipart)
    const boundary = '----FormBoundary' + Math.random().toString(36).slice(2);
    const body = `--${boundary}\r\nContent-Disposition: form-data; name="file"; filename="test.pdf"\r\nContent-Type: application/pdf\r\n\r\n%PDF-test\r\n--${boundary}--\r\n`;
    const uploadRes = http.post(
        `${BASE_URL}/invoices/upload`,
        body,
        { headers: { ...params.headers, 'Content-Type': `multipart/form-data; boundary=${boundary}` } }
    );
    invoiceUploadDuration.add(uploadRes.timings.duration);
    errorRate.add(uploadRes.status !== 201);

    sleep(1);
}
```

```python
@task
def build_pgo(ctx):
    """Kompilacja Nuitka z PGO na podstawie profilowania."""
```

2. Kompilacja Nuitka w monorepo uv workspaces

Cel

Poprawne łączenie pakietów z uv workspaces w jedną binarkę Nuitka.

Rozwiązanie: Skrypt "spłaszczający" workspace

2.1. Skrypt Invoke tasks.py

```python
import shutil
from pathlib import Path
from invoke import task

@task
def flatten_workspace(ctx, target="build/flat"):
    """Kopiuje wszystkie pakiety workspaces do jednego katalogu."""
    target_path = Path(target)
    target_path.mkdir(parents=True, exist_ok=True)

    # Główne pakiety z pyproject.toml [tool.uv.workspace].members
    members = ["libs/domain", "apps/api", "apps/workers", "apps/integrations"]

    for member in members:
        src = Path(member)
        dst = target_path / src.name
        if src.exists():
            if dst.exists():
                shutil.rmtree(dst)
            shutil.copytree(src, dst, dirs_exist_ok=True)

    # Kopiuj też główny kod, jeśli jest poza workspaces
    for extra in ["core", "models", "pipeline", "services", "db"]:
        src = Path(extra)
        if src.exists():
            dst = target_path / extra
            if dst.exists():
                shutil.rmtree(dst)
            shutil.copytree(src, dst, dirs_exist_ok=True)

    print(f"Workspace spłaszczony do {target_path}")

@task(flatten_workspace)
def build_nuitka(ctx):
    """Pełna kompilacja Nuitka po spłaszczeniu."""
    ctx.run(
        "python -m nuitka --standalone --onefile "
        "--include-package=libs.domain --include-package=apps.api "
        "--include-package=apps.workers --include-package=apps.integrations "
        "--include-package=core --include-package=models --include-package=pipeline "
        "--include-package=services --include-package=db "
        "--include-data-dir=models=models "
        "--output-dir=dist --output-filename=nexusai "
        "build/flat/apps/api/server.py"
    )
```

```python
import gettext
from pathlib import Path

_locales = {}

def setup_i18n(lang: str = "pl"):
    locale_dir = Path(__file__).parent.parent / "locales"
    translation = gettext.translation("nexus", localedir=locale_dir, languages=[lang], fallback=True)
    translation.install()
    _locales["current"] = translation
    return translation

def _(msgid: str) -> str:
    return _locales.get("current", gettext.NullTranslations()).gettext(msgid)
```

```python
import json
from pathlib import Path

def load_translations(lang: str) -> dict:
    path = Path(__file__).parent / "i18n" / f"{lang}.json"
    return json.loads(path.read_text(encoding="utf-8"))

class I18n:
    def __init__(self, lang="pl"):
        self.lang = lang
        self.strings = load_translations(lang)

    def t(self, key: str) -> str:
        return self.strings.get(key, key)

# W flet_main:
```

6. Tryb offline dla Infisical

Cel

Umożliwienie startu aplikacji bez dostępu do Infisical.

Rozwiązanie: Zaszyfrowany lokalny cache z SOPS + Age

6.1. Moduł core/secrets_cache.py

```python
import json
import os
import subprocess
from datetime import datetime, timezone, timedelta
from pathlib import Path

CACHE_PATH = Path("/var/lib/nexus/secrets_cache.enc")
CACHE_TTL_HOURS = 24

def fetch_from_infisical() -> dict:
    """Pobiera sekrety z Infisical (HTTP API)."""
    import httpx
    resp = httpx.get(
        "https://infisical.example.com/api/v3/secrets",
        headers={"Authorization": f"Bearer {os.getenv('INFISICAL_TOKEN')}"},
        timeout=5.0
    )
    resp.raise_for_status()
    return resp.json()

def save_cache(secrets: dict):
    """Zapisuje sekrety do pliku szyfrowanego SOPS."""
    plain_path = CACHE_PATH.with_suffix(".tmp.json")
    plain_path.write_text(json.dumps(secrets))
    subprocess.run(["sops", "-e", "-i", str(plain_path)], check=True)
    plain_path.rename(CACHE_PATH)

def load_cache() -> dict:
    """Odczytuje i deszyfruje cache."""
    if not CACHE_PATH.exists():
        return None
    plain = subprocess.check_output(["sops", "-d", str(CACHE_PATH)], text=True)
    return json.loads(plain)

def need_refresh(metadata_path="/var/lib/nexus/cache_meta.json") -> bool:
    path = Path(metadata_path)
    if not path.exists():
        return True
    meta = json.loads(path.read_text())
    last = datetime.fromisoformat(meta["last_fetch"])
    return (datetime.now(timezone.utc) - last) > timedelta(hours=CACHE_TTL_HOURS)

def get_secrets():
    """Główna funkcja – pobiera sekrety z cache lub Infisical."""
    if not need_refresh():
        return load_cache()
    try:
        secrets = fetch_from_infisical()
        save_cache(secrets)
        return secrets
    except Exception:
        # Fallback do cache
        cached = load_cache()
        if cached:
            return cached
        raise RuntimeError("Cannot fetch secrets and no cache available")
```

```python
from datetime import datetime, timedelta
from db.analytics import DuckDBManager
from core.logger import logger

# Wzorce dla polskich danych wrażliwych
PATTERNS = {
    "NIP": re.compile(r'\b(\d{3}[- ]?\d{3}[- ]?\d{2}[- ]?\d{2})\b'),
    "PESEL": re.compile(r'\b(\d{11})\b'),
    "REGON": re.compile(r'\b(\d{9}|\d{14})\b'),
    "BANK_ACCOUNT": re.compile(r'\b(PL\d{26}|\d{26})\b'),
}

class LogScanner:
    def __init__(self, duckdb: DuckDBManager):
        self.duckdb = duckdb

    def scan_last_24h(self) -> list[dict]:
        """Skanuje logi z ostatnich 24h z Parquet."""
        query = """
        SELECT timestamp, correlation_id, message
        FROM read_parquet('/var/log/nexus/*.parquet')
        WHERE timestamp >= current_date - INTERVAL 1 DAY
        """
        rows = self.duckdb.execute(query)
        findings = []
        for timestamp, corr_id, message in rows:
            for data_type, pattern in PATTERNS.items():
                matches = pattern.findall(str(message))
                for match in matches:
                    findings.append({
                        "timestamp": timestamp,
                        "correlation_id": corr_id,
                        "data_type": data_type,
                        "value": match
                    })
        return findings

    async def run_and_alert(self, nats_client):
        findings = self.scan_last_24h()
        if findings:
            await nats_client.publish(
                "alerts.gdpr.leak_detected",
                json.dumps({"findings_count": len(findings), "sample": findings[:5]}).encode()
            )
```

9. Polityka wycofywania wersji modeli AI (Model Registry)

Cel

Zapobieganie wyczerpaniu dysku przez stare modele.

Rozwiązanie: Automatyczne archiwizowanie i retencja

9.1. Moduł ml/model_registry.py

```python
import json
import shutil
from datetime import datetime, timezone
from pathlib import Path
from db.analytics import DuckDBManager

MODELS_ROOT = Path("/data/models")
ARCHIVE_ROOT = Path("/data/archive/models")
MAX_ACTIVE_VERSIONS = 3 # przechowuj max 3 aktywne wersje

class ModelRegistry:
    def __init__(self, duckdb: DuckDBManager):
        self.duckdb = duckdb
        self._ensure_schema()

    def _ensure_schema(self):
        self.duckdb.execute("""
        CREATE TABLE IF NOT EXISTS model_registry (
            model_name VARCHAR,
            version VARCHAR,
            path VARCHAR,
            metrics JSON,
            created_at TIMESTAMP DEFAULT now(),
            is_active BOOLEAN DEFAULT FALSE,
            PRIMARY KEY (model_name, version)
        )
        """)

    def register_version(self, model_name: str, version: str, path: Path, metrics: dict):
        self.duckdb.execute(
            "INSERT OR REPLACE INTO model_registry (model_name, version, path, metrics, is_active) VALUES (?, ?, ?, ?, ?)",
            (model_name, version, str(path), json.dumps(metrics), True)
        )
        self._enforce_retention(model_name)

    def _enforce_retention(self, model_name: str):
        """Archiwizuje nadmiarowe wersje."""
        rows = self.duckdb.execute(
            "SELECT version, path FROM model_registry WHERE model_name = ? ORDER BY created_at DESC",
            (model_name,)
        )
        active = rows[:MAX_ACTIVE_VERSIONS]
        to_archive = rows[MAX_ACTIVE_VERSIONS:]

        for version, path in to_archive:
            src = Path(path)
            dst = ARCHIVE_ROOT / model_name / version
            dst.parent.mkdir(parents=True, exist_ok=True)
            if src.exists():
                shutil.move(str(src), str(dst))
            self.duckdb.execute(
                "UPDATE model_registry SET is_active = FALSE, path = ? WHERE model_name = ? AND version = ?",
                (str(dst), model_name, version)
            )

    def promote_model(self, model_name: str, version: str):
        """Aktywuje wybraną wersję modelu."""
        self.duckdb.execute(
            "UPDATE model_registry SET is_active = (model_name = ? AND version = ?)",
            (model_name, version)
        )
```

```python
            SUM(ram_gb) * {ram_rate} / 24 as ram_cost,
```

1. Brak procedury migracji istniejących faktur na Event Sourcing (Data Backfill)

Problem

Obecny kod przechowuje faktury bezpośrednio w SQLite (tabela invoices).                     "amount_gross": str(row[4]),

```python
                    "file_path": row[8] or "",
                },
                "metadata": {

            await session.execute(

                {"id": invoice_id},

            print(f"Migrated invoice {invoice_id}")

    await nc.close()

if __name__ == "__main__":
```

2. Konflikt między trybem WAL SQLite a LiteFS

Problem

SQLite w trybie WAL (Write-Ahead Logging) tworzy osobne pliki -wal i -shm. LiteFS do replikacji wymaga, aby baza była w trybie WAL, ale niektóre operacje (np. VACUUM, PRAGMA journal_mode=DELETE) mogą tymczasowo wyłączyć WAL, co przerywa replikację. Ponadto LiteFS wymaga, aby aplikacja używała specjalnego API do blokowania zapisów na replikach (fencing).

Ryzyko

Niewłaściwa konfiguracja spowoduje, że repliki nie będą synchronizowane lub dojdzie do uszkodzenia bazy przy próbie zapisu na replice.

Rozwiązanie dla CodeX: Konfiguracja LiteFS + hooki w aplikacji

Krok 1: Wymuszenie WAL i odpowiednich PRAGMA

W db/database.py przy tworzeniu silnika:

```python
from sqlalchemy import event

@event.listens_for(async_engine.sync_engine, "connect")
def set_sqlite_pragmas(dbapi_connection, connection_record):
    cursor = dbapi_connection.cursor()
    cursor.execute("PRAGMA journal_mode=WAL;")
    cursor.execute("PRAGMA synchronous=NORMAL;")
    cursor.execute("PRAGMA busy_timeout=5000;")
    cursor.execute("PRAGMA wal_autocheckpoint=1000;") # częstsze checkpointy dla LiteFS
    cursor.close()
```

```python
# services/taskiq_relay.py
async def taskiq_outbox_relay(session_factory, taskiq_broker):
    while True:
        async with session_factory() as session:
            result = await session.execute(
                select(TaskiqOutbox).where(TaskiqOutbox.status == "PENDING").limit(10)
            )
            entries = result.scalars().all()
            for entry in entries:
                try:
                    await taskiq_broker.kick(entry.task_name, **json.loads(entry.payload))
                    entry.status = "SENT"
                    await session.commit()
                except Exception as e:
                    entry.retry_count += 1
                    if entry.retry_count >= entry.max_retries:
                        entry.status = "FAILED"
                    await session.commit()
                    # Loguj do Sentry
                    logger.error(f"Taskiq kick failed for {entry.id}: {e}")
        await asyncio.sleep(1)
```

```python
# frontend/token_manager.py
import httpx
import time
from frontend.api_client import NexusAPIClientUI

class TokenManager:
    def __init__(self, api_client: NexusAPIClientUI, refresh_before_seconds=300):
        self.api_client = api_client
        self.refresh_before_seconds = refresh_before_seconds
        self.expires_at = 0

    async def ensure_valid_token(self):
        if time.time() + self.refresh_before_seconds > self.expires_at:
            await self.refresh()

    async def refresh(self):
        async with httpx.AsyncClient() as client:
            resp = await client.post(
                f"{self.api_client.base_url}/auth/refresh",
                cookies=self.api_client._client.cookies
            )
            if resp.status_code == 200:
                data = resp.json()
                self.api_client.access_token = data["access_token"]
                self.api_client._client.headers["Authorization"] = f"Bearer {data['access_token']}"
                # Dekoduj JWT aby odczytać nowy expires_at
                import jwt
                payload = jwt.decode(data["access_token"], options={"verify_signature": False})
                self.expires_at = payload["exp"]
```

```python
@dataclass(slots=True)
class AppConfig:
    # Kolejność priorytetu:
    # 1. Zmienna środowiskowa (dla szybkiego override)
    # 2. Infiscal (dla sekretów runtime)
    # 3. Plik SOPS (dla konfiguracji domyślnych, zaszyfrowanych)
    jwt_secret: str = field(default_factory=lambda: _resolve_secret("NEXUS_JWT_SECRET"))

def _resolve_secret(key: str) -> str:
    # 1. Zmienna środowiskowa
    env_val = os.getenv(key)
    if env_val:
        return env_val
    # 2. Infiscal (jeśli dostępny)
    try:
        from core.secrets_cache import get_secrets
        secrets = get_secrets()
        if key in secrets:
            return secrets[key]
    except Exception:
        pass
    # 3. Plik SOPS (odszyfrowany)
    sops_path = Path(f"/etc/nexus/secrets/{key}.enc")
    if sops_path.exists():
        import subprocess
        return subprocess.check_output(["sops", "-d", str(sops_path)], text=True).strip()
    raise ConfigValidationError(f"Missing secret: {key}")
```

```python
class AsyncFsspecStorage:
    async def save_invoice_smart(self, upload_file: UploadFile) -> dict:
        loop = asyncio.get_running_loop()
        chunks = []
        temp_path = self.base_path / f"temp_{uuid4()}_{upload_file.filename}"

        # Zapis do pliku tymczasowego
        with self.fs.open(str(temp_path), "wb") as f:
            while content := await upload_file.read(1024 * 1024):
                f.write(content)
                chunks.append(content)

        digest = await loop.run_in_executor(None, compute_hash_sync, chunks)
        final_dir = self.base_path / digest[:2] / digest[2:4]
        final_path = final_dir / f"{digest}.pdf"

        # Atomowe przeniesienie (jeśli plik już istnieje, operacja się nie uda)
        try:
            self.fs.makedirs(str(final_dir), exist_ok=True)
            # Użyj rename, który jest atomowy na większości systemów plików
            self.fs.mv(str(temp_path), str(final_path))
        except FileExistsError:
            # Plik już istnieje – usuń tymczasowy i zwróć istniejący
            self.fs.rm(str(temp_path))
            return {
                "hash": digest,
                "path": str(final_path),
                "size": self.fs.size(str(final_path)),
                "deduplicated": True
            }

        return {"hash": digest, "path": str(final_path), "size": len(b"".join(chunks)), "deduplicated": False}
```

Krok 1: Implementacja ml/model_cache.py

```python
import torch
from collections import OrderedDict
from threading import Lock

class LRUModelCache:
    def __init__(self, max_size=3):
        self.cache = OrderedDict()
        self.lock = Lock()
        self.max_size = max_size

    def get_or_load(self, tenant_id: str, base_model: torch.nn.Module, lora_path: str) -> torch.nn.Module:
        with self.lock:
            if tenant_id in self.cache:
                self.cache.move_to_end(tenant_id)
                return self.cache[tenant_id]
            # Załaduj adapter
            if len(self.cache) >= self.max_size:
                # Usuń najstarszy (LRU)
                oldest_tenant, oldest_model = self.cache.popitem(last=False)
                # Przenieś na CPU, aby zwolnić VRAM
                oldest_model.to("cpu")
                torch.cuda.empty_cache()
            model = copy.deepcopy(base_model)
            model.load_adapter(lora_path)
            model.to("cuda")
            self.cache[tenant_id] = model
            return model
```

Opis

System automatycznie dopasowuje faktury do transakcji bankowych, używając wielowymiarowego fuzzy matchingu i uczenia aktywnego. Gdy pewność dopasowania jest wysoka – faktura jest automatycznie oznaczana jako opłacona. Gdy pewność jest średnia – sugerowane jest dopasowanie do akceptacji księgowego. Gdy niska – faktura trafia na listę nierozliczonych.

Dlaczego to ważne

Ręczne uzgadnianie setek faktur z wyciągami bankowymi jest czasochłonne i błędogenne. Automatyzacja oszczędza godziny pracy miesięcznie.

Implementacja (szczegółowa)

Krok 1: Model danych w DuckDB

```sql

    invoice_id VARCHAR,
    bank_transaction_id VARCHAR,
    match_score DOUBLE,
    status VARCHAR DEFAULT 'PENDING', -- PENDING, AUTO_MATCHED, SUGGESTED, CONFIRMED, REJECTED
    confirmed_by VARCHAR,
    confirmed_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT now()
```

Krok 2: Silnik dopasowujący z uczeniem aktywnym

```python
# services/reconciliation/smart_matcher.py
import polars as pl
from datetime import datetime, timedelta
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.preprocessing import StandardScaler
import joblib
from pathlib import Path

class SmartReconciliationEngine:
    """Silnik uzgadniania z uczeniem maszynowym."""

    def __init__(self, duckdb_manager, lancedb_manager, model_path: str = "models/reconciliation_model.joblib"):
        self.duckdb = duckdb_manager
        self.lancedb = lancedb_manager
        self.model_path = Path(model_path)
        self.scaler_path = self.model_path.with_suffix('.scaler')
        self.model = None
        self.scaler = None
        self._load_model()

    def _load_model(self):
        if self.model_path.exists():
            self.model = joblib.load(self.model_path)
            self.scaler = joblib.load(self.scaler_path)

    def _compute_features(self, invoice: dict, tx: dict) -> dict:
        """Oblicza wektor cech dla pary faktura-transakcja."""
        inv_date = datetime.fromisoformat(invoice['due_date'])
        tx_date = datetime.fromisoformat(tx['booking_date'])
        amount_diff = abs(float(invoice['amount_gross']) - float(tx['amount']))
        days_diff = abs((inv_date - tx_date).days)

        # Podobieństwo tytułów (TF-IDF cosine)
        from sklearn.feature_extraction.text import TfidfVectorizer
        vectorizer = TfidfVectorizer(analyzer='char', ngram_range=(2, 3))
        tfidf = vectorizer.fit_transform([invoice.get('title', ''), tx.get('title', '')])
        title_sim = (tfidf * tfidf.T).toarray()[0][1]

        return {
            'amount_diff_ratio': amount_diff / max(float(invoice['amount_gross']), 1),
            'days_diff': days_diff,
            'title_similarity': title_sim,
            'same_currency': 1 if invoice.get('currency') == tx.get('currency') else 0,
            'vendor_history_score': self._get_vendor_score(invoice.get('contractor_nip')),
        }

    def _get_vendor_score(self, nip: str) -> float:
        """Pobiera historyczny współczynnik poprawności dopasowań dla NIP."""
        row = self.duckdb.execute(
            "SELECT AVG(CASE WHEN status = 'CONFIRMED' THEN match_score ELSE 0 END) FROM bank_reconciliation r JOIN invoices_replica i ON r.invoice_id = i.id WHERE i.contractor_nip = ?",
            (nip,)
        ).fetchone()
        return float(row[0]) if row and row[0] else 0.5

    async def find_matches(self, invoice_id: str) -> dict:
        """Znajduje najlepsze dopasowanie dla faktury."""
        invoice = self.duckdb.execute(
            "SELECT * FROM invoices_replica WHERE id = ?", (invoice_id,)
        ).fetchone()
        if not invoice:
            return {"status": "INVOICE_NOT_FOUND"}

        inv_dict = dict(invoice)
        # Pobierz transakcje bankowe w oknie +/- 5 dni
        bank_txs = self.duckdb.execute(
            "SELECT * FROM bank_transactions WHERE booking_date BETWEEN ? AND ?",
            (inv_dict['due_date'], (datetime.fromisoformat(inv_dict['due_date']) + timedelta(days=5)).isoformat())
        ).fetchall()

        best_score = 0
        best_match = None
        matches = []

        for tx in bank_txs:
            tx_dict = dict(tx)
            features = self._compute_features(inv_dict, tx_dict)

            if self.model:
                X = self.scaler.transform([[v for v in features.values()]])
                score = self.model.predict_proba(X)[0][1]
            else:
                # Heurystyka wagowa jako fallback
                score = (
                    0.4 * (1 - features['amount_diff_ratio']) +
                    0.3 * (1 - min(features['days_diff'] / 10, 1)) +
                    0.2 * features['title_similarity'] +
                    0.1 * features['vendor_history_score']
                )

            matches.append({
                'transaction_id': tx_dict['id'],
                'score': score,
                'features': features
            })
            if score > best_score:
                best_score = score
                best_match = tx_dict

        result = {
            'invoice_id': invoice_id,
            'matches': sorted(matches, key=lambda x: x['score'], reverse=True)[:5]
        }

        if best_score > 0.95:
            result['status'] = 'AUTO_MATCHED'
            result['matched_transaction_id'] = best_match['id']
            # Automatycznie oznacz jako opłacone
            await self._auto_settle(invoice_id, best_match['id'])
        elif best_score > 0.7:
            result['status'] = 'SUGGESTED_MATCH'
            result['suggested_transaction_id'] = best_match['id']
        else:
            result['status'] = 'UNMATCHED'

        # Zapisz do bazy
        for match in matches:
            self.duckdb.execute(
                "INSERT OR REPLACE INTO bank_reconciliation (id, invoice_id, bank_transaction_id, match_score, status) VALUES (?, ?, ?, ?, ?)",
                (str(uuid4()), invoice_id, match['transaction_id'], match['score'], result['status'])
            )

        return result

    async def _auto_settle(self, invoice_id: str, tx_id: str):
        """Automatycznie oznacza fakturę jako opłaconą."""
        self.duckdb.execute(
            "UPDATE invoices_replica SET status = 'PAID', paid_at = now() WHERE id = ?",
            (invoice_id,)
        )
        await self.nats_client.publish("invoice.paid", json.dumps({"invoice_id": invoice_id, "tx_id": tx_id}).encode())

    async def train_model(self):
        """Trenuje model na historycznych, potwierdzonych dopasowaniach."""
        data = self.duckdb.execute("""
            SELECT i.amount_gross, b.amount, i.due_date, b.booking_date, i.contractor_nip, i.title as inv_title, b.title as tx_title
            FROM bank_reconciliation r
            JOIN invoices_replica i ON r.invoice_id = i.id
            JOIN bank_transactions b ON r.bank_transaction_id = b.id
            WHERE r.status IN ('CONFIRMED', 'REJECTED')
        """).fetchall()

        if len(data) < 50:
            return # za mało danych

        X = []
        y = []
        for row in data:
            inv = {'amount_gross': row[0], 'due_date': row[2], 'contractor_nip': row[4], 'title': row[5]}
            tx = {'amount': row[1], 'booking_date': row[3], 'title': row[6]}
            features = self._compute_features(inv, tx)
            X.append([v for v in features.values()])
            y.append(1 if row['status'] == 'CONFIRMED' else 0)

        self.scaler = StandardScaler()
        X = self.scaler.fit_transform(X)
        self.model = GradientBoostingClassifier(n_estimators=100)
        self.model.fit(X, y)

        joblib.dump(self.model, self.model_path)
        joblib.dump(self.scaler, self.scaler_path)
```

```python
# services/rules/engine.py
import json
from sqlalchemy import select

class RulesEngine:
    def __init__(self, session_factory, nats_client):
        self.session_factory = session_factory
        self.nats_client = nats_client
        self._cache = {}
        self._last_refresh = None

    async def _refresh_cache(self):
        """Odświeża cache reguł z bazy (wywoływane przez NATS lub okresowo)."""
        async with self.session_factory() as session:
            result = await session.execute(
                select(BusinessRule).where(BusinessRule.is_active == True).order_by(BusinessRule.priority)
            )
            self._cache = {rule.name: rule for rule in result.scalars().all()}
            self._last_refresh = datetime.now(timezone.utc)

    async def evaluate(self, entity_type: str, entity_data: dict) -> list[str]:
        """Ocenia wszystkie reguły dla encji. Zwraca listę akcji do wykonania."""
        if not self._cache:
            await self._refresh_cache()
        actions = []
        for rule_name, rule in self._cache.items():
            if rule.applies_to != entity_type:
                continue
            # Wykonaj warunek SQL z parametryzacją
            async with self.session_factory() as session:
                try:
                    result = await session.execute(
                        text(f"SELECT CASE WHEN {rule.condition_sql} THEN 1 ELSE 0 END"),
                        entity_data
                    )
                    if result.scalar():
                        actions.append(rule.action)
                        # Publikuj zdarzenie o naruszeniu reguły
                        await self.nats_client.publish(
                            "rules.violation",
                            json.dumps({"rule": rule_name, "entity": entity_data, "action": rule.action}).encode()
                        )
                except Exception as e:
                    logger.error(f"Rule {rule_name} evaluation failed: {e}")
        return actions

    async def hot_reload_listener(self):
        """Nasłuchuje na NATS na zmiany reguł."""
        sub = await self.nats_client.subscribe("rules.reload")
        async for msg in sub.messages:
            await self._refresh_cache()
            logger.info("Rules cache reloaded via NATS")
```

3. Zaawansowane Prognozowanie Cashflow z Prophet i Analizą Sezonowości

Opis

System przewiduje przyszłe saldo firmy na podstawie 2-3 lat historii, uwzględniając sezonowość tygodniową/roczną, polskie święta i indywidualne wzorce płatności kontrahentów.

Implementacja

```python
# services/forecasting/prophet_engine.py
from prophet import Prophet
import polars as pl

class ProphetCashflowEngine:
    def __init__(self, duckdb_manager):
        self.duckdb = duckdb_manager
        self.model = None

    async def train(self):
        """Trenuje model na danych historycznych."""
        df = self.duckdb.execute("""
            SELECT
                CAST(issue_date AS DATE) as ds,
                SUM(CASE WHEN type = 'SALE' THEN amount_gross ELSE -amount_gross END) as y
            FROM invoices_replica
            WHERE issue_date >= CURRENT_DATE - INTERVAL 3 YEAR
            GROUP BY 1 ORDER BY 1
        """).pl().to_pandas()

        df.columns = ['ds', 'y']
        df['ds'] = pd.to_datetime(df['ds'])

        self.model = Prophet(
            yearly_seasonality=True,
            weekly_seasonality=True,
            daily_seasonality=False,
            changepoint_prior_scale=0.05,
            seasonality_prior_scale=10.0,
        )
        self.model.add_country_holidays(country_name='PL')
        # Dodaj specyficzne okresy (koniec roku podatkowego)
        self.model.add_seasonality(name='monthly', period=30.5, fourier_order=5)
        self.model.fit(df)

    async def forecast(self, days_ahead: int = 90) -> pl.DataFrame:
        """Zwraca prognozę na X dni naprzód."""
        if not self.model:
            await self.train()
        future = self.model.make_future_dataframe(periods=days_ahead)
        forecast = self.model.predict(future)
        result = forecast[['ds', 'yhat', 'yhat_lower', 'yhat_upper']].tail(days_ahead)
        return pl.from_pandas(result)

    async def detect_cash_crisis(self):
        """Wykrywa potencjalne problemy z płynnością."""
        forecast = await self.forecast(30)
        min_balance = forecast['yhat'].min()
        if min_balance < 0:
            crisis_date = forecast.filter(pl.col('yhat') < 0)['ds'].min()
            alert_msg = f"Przewidywany deficyt środków {abs(min_balance):.2f} PLN dnia {crisis_date}"
            await self.nats_client.publish("alerts.cashflow.crisis", alert_msg.encode())
            return {"crisis": True, "date": crisis_date, "deficit": abs(min_balance)}
        return {"crisis": False}
```

4. Wykrywanie Fałszerstw Wizualnych Faktur (Error Level Analysis + CNN)

Opis

System analizuje obrazy faktur pod kątem manipulacji graficznych (np. przerobiona kwota w edytorze graficznym). Wykorzystuje Error Level Analysis (ELA) i lekką konwolucyjną sieć neuronową.

Implementacja

```python
# pipeline/fraud_detector.py
import torch
import torch.nn as nn
import cv2
import numpy as np

class VisualFraudDetector(nn.Module):
    """Wykrywa manipulacje graficzne metodą Error Level Analysis."""

    def __init__(self):
        super().__init__()
        self.feature_extractor = nn.Sequential(
            nn.Conv2d(3, 64, kernel_size=5, padding=2),
            nn.ReLU(),
            nn.BatchNorm2d(64),
            nn.MaxPool2d(2),
            nn.Conv2d(64, 128, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.BatchNorm2d(128),
            nn.MaxPool2d(2),
            nn.Conv2d(128, 256, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.AdaptiveAvgPool2d((1, 1)),
        )
        self.classifier = nn.Sequential(
            nn.Flatten(),
            nn.Linear(256, 64),
            nn.ReLU(),
            nn.Dropout(0.3),
            nn.Linear(64, 1),
            nn.Sigmoid()
        )

    def forward(self, x):
        features = self.feature_extractor(x)
        return self.classifier(features)

    @staticmethod
    def compute_ela(image_path: str, quality: int = 90) -> np.ndarray:
        """Error Level Analysis – uwydatnia miejsca edytowane."""
        import tempfile
        original = cv2.imread(image_path)
        # Zapisz jako JPEG z obniżoną jakością
        with tempfile.NamedTemporaryFile(suffix='.jpg', delete=True) as tmp:
            cv2.imwrite(tmp.name, original, [cv2.IMWRITE_JPEG_QUALITY, quality])
            compressed = cv2.imread(tmp.name)
        # Różnica = obszary o innej historii kompresji
        ela = cv2.absdiff(original, compressed)
        ela = cv2.cvtColor(ela, cv2.COLOR_BGR2GRAY)
        ela = cv2.equalizeHist(ela) # wzmocnienie kontrastu
        return ela

    def predict(self, image_path: str) -> dict:
        ela = self.compute_ela(image_path)
        ela_rgb = cv2.cvtColor(ela, cv2.COLOR_GRAY2RGB)
        tensor = torch.from_numpy(ela_rgb).permute(2, 0, 1).unsqueeze(0).float() / 255.0
        with torch.inference_mode():
            score = self.forward(tensor).item()
        return {
            "is_suspicious": score > 0.7,
            "fraud_score": score,
            "ela_image": ela # do wyświetlenia w UI
        }
```

5. Inteligentny Asystent Księgowego (RAG Copilot) z Wyjaśnialnością

Opis

Gdy księgowy otwiera fakturę, system automatycznie generuje kontekstowe podsumowanie: historię kontrahenta, podobne faktury z przeszłości, sugerowane konto księgowe i alerty (np. zmiana numeru konta). Wykorzystuje LanceDB do wyszukiwania semantycznego i lokalny LLM (Phi-3) do generowania podsumowań.

Implementacja

```python
# services/copilot/rag_copilot.py
from sentence_transformers import SentenceTransformer
import lancedb

class AuditCopilot:
    def __init__(self, duckdb_manager, lancedb_manager, llm_engine):
        self.duckdb = duckdb_manager
        self.lancedb = lancedb_manager
        self.llm = llm_engine
        self.encoder = SentenceTransformer('sdadas/st-polish-paraphrase-distilled')

    async def analyze_invoice(self, invoice_id: str) -> dict:
        """Generuje raport dla księgowego."""
        invoice = self.duckdb.execute(
            "SELECT * FROM invoices_replica WHERE id = ?", (invoice_id,)
        ).fetchone()
        if not invoice:
            return {"error": "Invoice not found"}

        nip = invoice[2] # contractor_nip
        amount = float(invoice[4]) # amount_gross

        # 1. Historia kontrahenta (LanceDB – podobne faktury)
        query_vector = self.encoder.encode(f"Faktura {nip} {amount}").tolist()
        similar = self.lancedb.table("invoice_vectors").search(query_vector).limit(5).to_list()

        # 2. Trendy z DuckDB
        history = self.duckdb.execute("""
            SELECT AVG(amount_gross), COUNT(*), MAX(issue_date)
            FROM invoices_replica
            WHERE contractor_nip = ? AND id != ?
        """, (nip, invoice_id)).fetchone()

        # 3. Alerty (zmiana konta?)
        last_bank_account = self.duckdb.execute("""
            SELECT bank_account FROM invoices_replica
            WHERE contractor_nip = ? AND bank_account IS NOT NULL
            ORDER BY issue_date DESC LIMIT 1
        """, (nip,)).fetchone()

        # 4. Generuj podsumowanie LLM
        prompt = f"""
        Jesteś asystentem księgowego. Przeanalizuj poniższe dane i napisz zwięzłe podsumowanie:
        - Kontrahent: {nip}
        - Kwota faktury: {amount:.2f} PLN
        - Średnia historyczna: {history[0]:.2f} PLN
        - Liczba faktur w historii: {history[1]}
        - Ostatnia faktura: {history[2]}
        - Podobne faktury znalezione: {len(similar)}
        {"- UWAGA: Numer konta bankowego różni się od poprzednich!" if last_bank_account and last_bank_account[0] != invoice.get('bank_account') else ""}
        """
        summary = await self.llm.generate(prompt)

        return {
            "summary": summary,
            "history": {
                "avg_amount": history[0],
                "count": history[1],
                "last_date": history[2]
            },
            "similar_invoices": similar,
            "alerts": [
                "ACCOUNT_CHANGED" if last_bank_account and last_bank_account[0] != invoice.get('bank_account') else None,
                "HIGH_AMOUNT" if amount > float(history[0] or 0) * 1.5 else None,
            ]
        }
```

6. System Reputacji Kontrahentów z Analizą Grafową

Opis

System buduje graf powiązań między kontrahentami na podstawie współdzielonych numerów kont bankowych, adresów i historii płatności. Na podstawie analizy grafowej (NetworkX) oblicza scoring ryzyka i wykrywa potencjalne powiązania (np. ten sam właściciel pod różnymi NIP-ami).

Implementacja

```python
# services/vendor_graph.py
import networkx as nx
from datetime import datetime, timedelta

class VendorGraphEngine:
    def __init__(self, duckdb_manager):
        self.duckdb = duckdb_manager

    def build_graph(self) -> nx.Graph:
        """Buduje graf kontrahentów z DuckDB."""
        G = nx.Graph()
        # Węzły – kontrahenci
        contractors = self.duckdb.execute(
            "SELECT DISTINCT contractor_nip, contractor_name FROM invoices_replica"
        ).fetchall()
        for nip, name in contractors:
            G.add_node(nip, name=name, type='CONTRACTOR')

        # Krawędzie – wspólny numer konta
        accounts = self.duckdb.execute("""
            SELECT contractor_nip, bank_account FROM invoices_replica
            WHERE bank_account IS NOT NULL
            GROUP BY 1, 2
        """).fetchall()
        for nip1, acc1 in accounts:
            for nip2, acc2 in accounts:
                if nip1 < nip2 and acc1 == acc2:
                    G.add_edge(nip1, nip2, relation='SHARED_ACCOUNT', weight=1.0)

        # Krawędzie – ten sam adres (jeśli dostępny)
        addresses = self.duckdb.execute("""
            SELECT contractor_nip, address FROM vendor_intelligence WHERE address IS NOT NULL
        """).fetchall()
        for nip1, addr1 in addresses:
            for nip2, addr2 in addresses:
                if nip1 < nip2 and addr1.strip().lower() == addr2.strip().lower():
                    G.add_edge(nip1, nip2, relation='SHARED_ADDRESS', weight=0.8)

        return G

    def detect_risk_clusters(self) -> list[dict]:
        """Wykrywa klastry kontrahentów o podwyższonym ryzyku."""
        G = self.build_graph()
        clusters = []
        for component in nx.connected_components(G):
            if len(component) > 1: # tylko grupy powiązane
                subgraph = G.subgraph(component)
                # Oblicz średnie opóźnienie płatności
                total_delay = 0
                for node in component:
                    delay = self.duckdb.execute(
                        "SELECT AVG(date_diff('day', due_date, payment_date)) FROM invoices_replica WHERE contractor_nip = ? AND status = 'PAID'",
                        (node,)
                    ).fetchone()[0] or 0
                    total_delay += delay
                avg_delay = total_delay / len(component)
                clusters.append({
                    "contractors": list(component),
                    "size": len(component),
                    "avg_payment_delay": avg_delay,
                    "risk_score": min(100, avg_delay * 10 + len(component) * 5)
                })
        return sorted(clusters, key=lambda x: x['risk_score'], reverse=True)
```

7. Symulator Podatkowy "What-If" (Tax Simulator)

Opis

Przed końcem roku system pozwala księgowemu zasymulować różne scenariusze podatkowe (np. zmiana formy opodatkowania) i porównać obciążenia podatkowe.

Implementacja

```python
# services/tax_simulator.py
import polars as pl

class TaxSimulator:
    def __init__(self, duckdb_manager):
        self.duckdb = duckdb_manager

    async def simulate(self, year: int, scenario: str) -> dict:
        """Symuluje podatki dla danego scenariusza."""
        data = self.duckdb.execute(f"""
            SELECT SUM(amount_net) as revenue, SUM(amount_gross - amount_net) as vat_output,
                   SUM(CASE WHEN type = 'PURCHASE' THEN amount_gross - amount_net ELSE 0 END) as vat_input
            FROM invoices_replica
            WHERE strftime('%Y', issue_date) = '{year}'
        """).fetchone()

        revenue = float(data[0] or 0)
        costs = float(data[0] or 0) * 0.6 # szacunkowe koszty 60%

        results = {}
        if scenario == 'scale':
            income = revenue - costs
            tax = income * 0.12 if income <= 120000 else (income - 120000) * 0.32 + 14400
            results = {"tax_form": "Skala podatkowa", "tax": tax, "effective_rate": tax / revenue if revenue else 0}
        elif scenario == 'linear':
            income = revenue - costs
            tax = income * 0.19
            results = {"tax_form": "Liniowy 19%", "tax": tax, "effective_rate": 0.19}
        elif scenario == 'lump_sum':
            # Różne stawki ryczałtu – uproszczona symulacja
            tax = revenue * 0.12 # domyślna stawka 12%
            results = {"tax_form": "Ryczałt 12%", "tax": tax, "effective_rate": 0.12}
        elif scenario == 'cit_estonian':
            # CIT Estoński – podatek tylko od wypłaconego zysku
            profit = revenue - costs
            tax = profit * 0.20 # przy wypłacie
            results = {"tax_form": "CIT Estoński", "tax": tax, "effective_rate": 0.20}

        results['scenario'] = scenario
        results['revenue'] = revenue
        results['costs'] = costs
        results['vat_due'] = max(0, float(data[1] or 0) - float(data[2] or 0))
        return results

    async def compare_all(self, year: int) -> pl.DataFrame:
        scenarios = ['scale', 'linear', 'lump_sum', 'cit_estonian']
        results = []
        for s in scenarios:
            r = await self.simulate(year, s)
            results.append(r)
        return pl.DataFrame(results).sort('tax')
```

8. Automatyczny Eksport JPK/VAT z Walidacją Krzyżową

Opis

System automatycznie generuje pliki JPK_V7 (deklaracja VAT) na podstawie danych z DuckDB, waliduje je przed wysyłką do KSeF i porównuje z danymi OCR (three-way match).

Implementacja

```python
# services/jpk_generator.py
from xsdata.formats.dataclass.serializers import XmlSerializer
from xsdata.formats.dataclass.parsers import XmlParser
from datetime import date

class JPKGenerator:
    def __init__(self, duckdb_manager):
        self.duckdb = duckdb_manager

    async def generate_jpk_v7(self, month: str) -> str:
        """Generuje plik JPK_V7 dla danego miesiąca."""
        data = self.duckdb.execute(f"""
            SELECT
                i.contractor_nip,
                i.number,
                i.issue_date,
                i.amount_net,
                i.amount_gross - i.amount_net as vat_amount,
                CASE WHEN i.type = 'SALE' THEN 'SPRZEDAZ' ELSE 'ZAKUP' END as transaction_type
            FROM invoices_replica i
            WHERE strftime('%Y-%m', i.issue_date) = '{month}'
              AND i.status IN ('APPROVED', 'PAID')
        """).fetchall()

        # Budowanie struktury XML JPK_V7
        xml_parts = []
        xml_parts.append('<?xml version="1.0" encoding="UTF-8"?>')
        xml_parts.append('<JPK_V7>')
        xml_parts.append(f'<Naglowek><DataWytworzenia>{date.today().isoformat()}</DataWytworzenia></Naglowek>')

        total_net = 0
        total_vat = 0
        for row in data:
            xml_parts.append(f'''
            <Ewidencja>
                <NIP>{row[0]}</NIP>
                <NumerFaktury>{row[1]}</NumerFaktury>
                <Data>{row[2]}</Data>
                <KwotaNetto>{row[3]}</KwotaNetto>
                <KwotaVAT>{row[4]}</KwotaVAT>
            </Ewidencja>
            ''')
            total_net += float(row[3] or 0)
            total_vat += float(row[4] or 0)

        xml_parts.append(f'<Podsumowanie><Netto>{total_net:.2f}</Netto><VAT>{total_vat:.2f}</VAT></Podsumowanie>')
        xml_parts.append('</JPK_V7>')
        return '\n'.join(xml_parts)

    async def validate_before_send(self, jpk_xml: str) -> dict:
        """Waliduje JPK przed wysyłką."""
        # 1. Walidacja struktury XML
        try:
            parser = XmlParser()
            parser.from_string(jpk_xml)
        except Exception as e:
            return {"valid": False, "error": f"XML parse error: {e}"}

        # 2. Three-way match z OCR i KSeF
        month_data = self._parse_month_from_jpk(jpk_xml)
        ocr_data = self.duckdb.execute(
            "SELECT SUM(amount_gross), SUM(amount_net) FROM ocr_results WHERE strftime('%Y-%m', issue_date) = ?",
            (month_data['month'],)
        ).fetchone()

        if ocr_data:
            if abs(float(ocr_data[0] or 0) - month_data['total_gross']) > 1.0:
                return {"valid": False, "error": "Mismatch between JPK and OCR totals"}

        return {"valid": True}
```

9. Auto-Scaling Workerów przez NATS i Pulumi (KEDA-like)

Opis

System monitoruje długość kolejki NATS i automatycznie uruchamia dodatkowe kontenery workerów, gdy kolejka rośnie, a gasi je, gdy spada do zera.

Implementacja

```python
# services/auto_scaler.py
import asyncio
import nats
from core.config import AppConfig

class NATSAutoScaler:
    def __init__(self, nats_url="nats://127.0.0.1:4222", min_workers=1, max_workers=10, scale_threshold=100):
        self.nats_url = nats_url
        self.min_workers = min_workers
        self.max_workers = max_workers
        self.scale_threshold = scale_threshold
        self.current_workers = min_workers

    async def run(self):
        nc = await nats.connect(self.nats_url)
        js = nc.jetstream()
        while True:
            stream = await js.stream_info("nexus_tasks")
            pending = stream.state.messages # liczba oczekujących wiadomości

            desired_workers = self.min_workers
            if pending > self.scale_threshold * 3:
                desired_workers = self.max_workers
            elif pending > self.scale_threshold:
                desired_workers = min(self.current_workers + 2, self.max_workers)
            elif pending < 10:
                desired_workers = self.min_workers

            if desired_workers != self.current_workers:
                # Wyślij sygnał do Pulumi przez webhook Coolify
                async with httpx.AsyncClient() as client:
                    await client.post(
                        "http://coolify:8000/api/v1/deploy",
                        json={"service": "nexus-worker", "replicas": desired_workers}
                    )
                self.current_workers = desired_workers
                print(f"Scaled workers from {self.current_workers} to {desired_workers} (pending: {pending})")

            await asyncio.sleep(30)
```

```python
GOLDEN_DIR = Path(__file__).parent / "golden"
```

6. System Powiadomień w Czasie Rzeczywistym (WebSocket + NATS)

Cel

Zamiast odpytywania API, stan faktur i alerty są wyświetlane natychmiast po zdarzeniu.

```python
# frontend/ws_listener.py
import asyncio
import json
import flet as ft

class RealtimeNotifier:
    def __init__(self, page: ft.Page):
        self.page = page
        self.subscriptions = {}
        self.ws = None

    async def connect(self):
        # Połącz przez NATS WebSocket
        import websockets
        token = self.page.client_storage.get("access_token")
        self.ws = await websockets.connect(f"ws://localhost:9222?token={token}")
        asyncio.create_task(self._listen())

    async def _listen(self):
        async for message in self.ws:
            data = json.loads(message)
            event_type = data.get("type")
            if event_type in self.subscriptions:
                for callback in self.subscriptions[event_type]:
                    await callback(data)

    def subscribe(self, event_type: str, callback):
        if event_type not in self.subscriptions:
            self.subscriptions[event_type] = []
            # Subskrybuj w NATS
            asyncio.create_task(self.ws.send(json.dumps({"action": "subscribe", "subject": event_type})))
        self.subscriptions[event_type].append(callback)

    async def show_toast(self, message: str, type="info"):
        color = {"info": ft.colors.BLUE, "success": ft.colors.GREEN, "error": ft.colors.RED, "warning": ft.colors.ORANGE}
        self.page.snack_bar = ft.SnackBar(
            content=ft.Text(message),
            bgcolor=color.get(type, ft.colors.BLUE),
            action="OK",
        )
        self.page.snack_bar.open = True
        self.page.update()
```

```python
# frontend/keyboard_manager.py
class KeyboardManager:
    SHORTCUTS = {
        "N": "/invoices/new",
        "U": "/upload",
        "F": "/search",
        "D": "/dashboard",
        "T": "/triage",
        "?": "/help",
        "Ctrl+S": "save_current",
        "Escape": "close_modal",
    }

    def __init__(self, page: ft.Page, router):
        self.page = page
        self.router = router

    def handle_key(self, e: ft.KeyboardEvent):
        key = e.key
        if e.ctrl and key == "S":
            self.page.pubsub.send_all("trigger_save")
            return
        if key == "Escape":
            self.page.close_dialog()
            return
        if key in self.SHORTCUTS:
            route = self.SHORTCUTS[key]
            if isinstance(route, str) and route.startswith("/"):
                self.router.navigate(route)

    def register(self):
        self.page.on_keyboard_event = self.handle_key
```
