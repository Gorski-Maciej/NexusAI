 3. DLACZEGO LICZBY SIĘ RÓŻNIĄ (3 METRYKI, 3 ODPOWIEDZI)
───────────────────────────────────────────────────────────────────────────────
  M1. Bloki matched:true  = ~7 560 (duża liczba NIE = pełne pokrycie prawne)
  M2. Unikalne rule_id    = 10 509 (ale 369 duplikatów, 512 stubów { true })
  M3. Punkty Doc 50       = 44/509 (8%) — najbardziej miarodajne dla prawa:
      to mapa punktów prawnych → reguł; 465 punktów NIE ma reguł.
  → Deklaracje README (90-100%) opierają się na M1/M2 (objętości reguł),
    a nie na M3 (pokryciu punktów prawnych). To jest źródło rozbieżności.

 4. KRYTYCZNE LUKI PRAWNE (PRIORYTETYZACJA — POZIOM ENTERPRISE)
───────────────────────────────────────────────────────────────────────────────
  P0 (natychmiast — ryzyko prawne/karno-skarbowe):
    • PCC: brak reguł dla wielu czynności (umowy, pożyczki, spółki, PCC-3/14 dni)
    • Podatki lokalne: nieruchomości (DN-1), środki transportowe — stawki gminne
    • Akcyza: paliwa/alkohol/tytoń/energia — częściowe (132 bloki, ale luki)
    • UoR: martwa warstwa PKPiR (56 reguł matched:false) — progi 2 mln EUR
  P1 (wysoki priorytet):
    • Cross-border/TP: <2% pokrycia — dokumentacje TP, CFC, rezydencja, FX
    • AML/BDO/RODO: ~5-25% — obowiązki ustawowe, sankcje, rejestry
    • Płace (Kodeks pracy): wynagrodzenia, urlopy, odprawy — JDG z pracownikami
  P2 (średni):
    • Zasiłki szczegółowe, karta podatkowa, sukcesja szczegóły, ryczałt stawki
    • 465 niezmapowanych punktów Doc 50 → automatyczna generacja reguł
      (narzędzie isap_crawler.py + generate_micro_rules.py już istnieją!)

───────────────────────────────────────────────────────────────────────────────
 5. ZGODNOŚĆ REGUŁ Z AKTAMI PRAWNYMI — OCENA JAKOŚCI
───────────────────────────────────────────────────────────────────────────────
  • Tylko 217 plików ma niepustą podstawę prawną (_legal_basis) — to znaczy,
    że ~47% plików rego nie deklaruje wprost artykułu ustawy.
  • Weryfikacja "reguła ↔ artykuł ustawy" nie jest zautomatyzowana end-to-end
    (narzędzia validate_legal_basis.py, legal_coverage_heatmap.py istnieją,
    ale nie ma bramki CI wymuszającej 100%).
  • Stuby { true } nie mogą mieć prawidłowej podstawy prawnej — to puste
    obietnice pokrycia.
  → Aby reguły były "zgodne z aktami prawnymi bez cienia wątpliwości",
    potrzebny jest SYSTEM: każda reguła → _legal_basis (artykuł+ustęp+pkt)
    + link do ISAP + test potwierdzający. Szczegóły w raporcie 04.

 6. WNIOSEK CZĘŚCI 2
───────────────────────────────────────────────────────────────────────────────
  NIE — reguły JDG NIE pokrywają dziś wszystkich przepisów prawnych ze
  wszystkich aktów z pliku Bbb. Pokrycie realne: ~55-65% obszarów A
  (VAT/PIT/ZUS/KKS/Ordynacja/KSeF), ale z lukami P0-P1 w PCC, lokalnych,
  akcyzie, UoR, cross-border, AML/RODO/BDO i płacach. Do "pokrycia
  wszystkich przepisów" potrzeba domknięcia ~465 punktów Doc 50 + eliminacji
  stubów + automatycznej weryfikacji podstaw prawnych (raport 04 i 05).
